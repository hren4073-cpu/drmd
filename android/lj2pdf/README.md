# LJ → PDF book (Android)

Нативное Android-приложение: скачивает блог **LiveJournal** постранично и
собирает из него **единый `book.pdf` с кликабельным оглавлением** — мобильный
аналог десктопного `httrack2pdf`.

В отличие от десктопной версии здесь **не нужны** ни Chrome, ни Ghostscript:
* рендер каждой страницы в PDF делает встроенный системный `WebView`
  (рисуется прямо на `PdfDocument`, с разбивкой длинных страниц на A4);
* склейку и оглавление — библиотека **PDFBox-Android** (`PDFMergerUtility`
  + `PDDocumentOutline`, кириллица в закладках поддерживается).

Интерфейс на **Material 3**. Конвертация идёт в **фоновом сервисе** с
уведомлением-прогрессом — приложение можно свернуть; по готовности тап по
уведомлению открывает книгу.

## Главный сценарий: «поставил на ночь — утром книга»

Как у torrent-архиватора. Для **LiveJournal**:

1. **Скан.** От первой страницы (`?skip=0,20,…`) приложение проходит весь блог
   и составляет его **структуру** — список постов (по пермалинкам `…/<id>.html`),
   само определяя, где блог заканчивается.
2. **Выбор объёма.** Показывает «Найдено N постов» и даёт выбрать, сколько
   сохранить, **начиная со свежих**: всё / половина / треть / своё число.
   *(Либо галка «Download everything automatically» — без вопросов, сразу всё:
   включил, убрал телефон, утром готовый PDF.)*
3. **Скачивание + сшивка.** Каждый выбранный пост открывается **целиком — с
   комментариями и медиа**, чистится от рекламы, рендерится в PDF; в конце —
   единый `book.pdf` с оглавлением по постам.

Долгие ночные прогоны держит **wake-lock** (работает с погашенным экраном) и
foreground-сервис; всё под уведомлением-прогрессом.

### Режимы
* **Full posts (with comments & media)** — качать страницы постов целиком
  (рекомендуется для архива). Если снять — берутся страницы-ленты `?skip=` (без
  комментариев, быстрее, но обрезанные превью).
* **Сайт с шаблоном** — произвольный URL с `{n}` + диапазон.
* **Одна страница** — один URL → один PDF.

**Без рекламы:** галка **«Remove ads / clean»** (вкл. по умолчанию) перед
рендером вычищает баннеры/промо (adsbygoogle, adfox/Яндекс, LJ-промо). Эвристика —
на разных темах LJ результат может отличаться.

Пример для теста: `https://technolirik.livejournal.com/` → режим LiveJournal,
**Full posts** вкл. → Start → скан → выбираешь объём → книга собирается в фоне.

## Куда сохраняется

По умолчанию — в приватную папку приложения; открывается кнопкой **Open PDF**.
Кнопкой **Folder** можно выбрать **свою папку** (системный выбор, SAF) —
готовый `book.pdf` дополнительно копируется туда (доступ запоминается).

## Как пользоваться

1. Выберите режим.
2. Введите URL (и при необходимости диапазон страниц).
3. *(необязательно)* **Folder** — выбрать папку для итогового PDF.
4. **Start** → конвертация идёт в фоне (смотрите уведомление).
5. **Open PDF** или тап по уведомлению — открыть готовую книгу.

## Сборка (Android Studio)

1. `File → Open…` и выберите папку `android_lj2pdf/`.
2. Дождитесь Gradle sync (нужен JDK 17 — встроен в свежие Android Studio).
3. **Build → Build APK(s)** или Run на устройстве/эмуляторе.
   APK появится в `app/build/outputs/apk/`.

> Командная строка `./gradlew assembleDebug` тоже работает, но в репозитории
> нет бинарного `gradle/wrapper/gradle-wrapper.jar`. Android Studio подставит
> свой Gradle автоматически; для CLI один раз выполните `gradle wrapper`
> (установленным Gradle 8.x), чтобы сгенерировать wrapper.

Параметры: `compileSdk 34`, `minSdk 21`, Kotlin 1.9, AGP 8.1.

## Структура

| Файл | Назначение |
|------|-----------|
| `MainActivity.kt` | Material-UI: выбор режима, параметры, выбор папки, запуск |
| `ConvertService.kt` | **фоновый** foreground-сервис: гонит конвейер + уведомления |
| `ConvertBus.kt` | связь сервис ↔ активность (прогресс/лог/результат) |
| `WebViewPdfRenderer.kt` | `WebView` → `PdfDocument` (рендер страницы в PDF) |
| `BookBuilder.kt` | слияние PDF + оглавление (PDFBox-Android) |

## Ограничения

* Печатается **полная** страница LJ (как в браузере, с комментариями) —
  HTML-очистка от рекламы из C-версии здесь пока не применяется.
* Для приватных/закрытых записей нужна авторизация — не поддерживается.
* Проверяйте `Entries/page`: если в блоге настроено иное число записей на
  страницу, подгоните его, иначе пагинация `?skip=` сдвинется.
